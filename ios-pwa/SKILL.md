# iOS PWA: как не наступать на грабли WebKit

Скилл собран из реальных фиксов боевой PWA (Nuxt 3 + Vue, но правила универсальны).
Каждое правило ниже — это баг, который уже стоил нескольких итераций. Цель: заложить
правильное решение **с первого раза**, потому что тестировать на живом iPhone
получается не всегда.

## Как пользоваться

1. **Перед написанием** фронтового кода для мобильных — пройди разделы, которые касаются задачи.
2. **При ревью/дебаге** «на iOS сломалось» — сначала сверься с разделом «Симптом → причина».
3. Если рядом с этим файлом есть папка `references/` — там подробности, история
   итераций и готовый код (`snippets/`). Читай нужный файл, когда задача глубже чек-листа.
4. Закончив задачу, дай пользователю **короткий сценарий ручной проверки на iPhone**
   (раздел «Проверка без айфона» в конце).

## Главные принципы

- **Различай три среды**: iOS Safari-вкладка, **установленная PWA (standalone)**, Android/десктоп.
  Многие баги есть только в standalone. Определяй standalone так:
  `navigator.standalone === true || matchMedia('(display-mode: standalone)').matches`.
- **iPadOS притворяется Mac**: iOS = `/iPhone|iPad|iPod/` **или** (`Macintosh`/`MacIntel` и `maxTouchPoints > 1`).
- **iOS-обходы включай точечно** (класс на `<html>`, только для iOS standalone и только для нужных роутов),
  а не глобально — иначе ломаешь Android и десктоп.
- **Не лечи вёрстку JS-ом на scroll/resize.** Переставлять элементы по `scroll`/`visualViewport.resize`
  на iOS = дрожание и мигание. Переключай режимы только на границах роутов/открытия модалок.
- **Каждый iOS-фикс закрепляй регрессионным тестом** (хотя бы тест на наличие/отсутствие CSS-правил)
  и комментарием в коде «почему так» со ссылкой на WebKit-баг. Иначе следующий рефакторинг вернёт баг.

## 1. Fixed-элементы и нижнее меню (dock / tab bar)

Симптомы: меню «скачет», уезжает вверх, рисуется посередине экрана при скролле,
мигает, отстаёт при инерционном скролле.

**Делай:**
- Рендери нижнее меню (и любые `position: fixed` оверлеи) **прямым ребёнком `<body>`**
  (Vue `<Teleport to="body">`, React `createPortal`). Любой предок с `transform`, `filter`,
  `contain`, `will-change`, `backdrop-filter`, `perspective` становится containing block
  и ломает fixed.
- На самом fixed-элементе меню **запрещены**: `transform` (включая `translate3d(0,0,0)`-«хак»),
  `will-change`, `contain`, `isolation`, `backface-visibility`, `backdrop-filter`,
  анимации/transition `opacity`/`transform`. Ставь `transition: none`.
  (Хак `translate3d` пробовали — стало хуже, откатили.)
- Отступ снизу: `padding-bottom: max(0.45rem, calc(env(safe-area-inset-bottom) - 0.75rem))`
  (или просто `env(safe-area-inset-bottom)`), meta viewport с `viewport-fit=cover`.
- Высоту меню измеряй `ResizeObserver` → CSS-переменная `--dock-height` → `padding-bottom`
  у контента. Пиши переменную **только если значение изменилось**. Не пересчитывай на
  `visualViewport.resize`.
- Табы делай `<button>` + `router.push`, а не `<a href>` (лишние навигации/подсветки в standalone).

**iOS 26 standalone (WebKit bugs 301172, 312149):** fixed/sticky элементы могут
рисоваться в координатах документа (посередине экрана) при скролле корня документа,
хотя `getBoundingClientRect` выглядит нормально. Рабочее решение — **в установленной iOS PWA
сделать скроллером `body`, а не документ**:

```css
/* включается классом только для iOS standalone и только на app-роутах */
html.ios-app-scroll { height: 100vh; height: 100dvh; min-height: 0; overflow: hidden; }
html.ios-app-scroll body {
  height: 100vh; height: 100dvh; min-height: 0;
  overflow-x: hidden; overflow-y: auto; overscroll-behavior-y: contain;
}
```

Следствия, о которых надо помнить сразу:
- `window.scrollY`/`window.scrollTo` больше не работают — заведи хелперы
  `getPageScrollTop()` / `setPageScrollTop()` / `getPageScroller()`, которые смотрят на класс
  и выбирают `document.body` или `window`. Используй их везде: восстановление скролла,
  бесконечная лента, «наверх», аналитика.
- Роутер сбрасывает скролл `window`, а не `body` → при переходе страница открывается
  «не сверху». Сбрасывай скролл body явно при входе на страницу (сразу, затем в `nextTick` +
  2×`requestAnimationFrame`).
- **Не** заменяй это на `body { position: fixed }` — в iOS PWA обрезает длинный контент.

## 2. Блокировка скролла под модалкой

- Блокируй через `overflow: hidden` на `html` **и** `body`. **Не** используй классический
  трюк `body { position: fixed; top: -scrollY }` — на iOS он меняет поведение fixed-потомков
  (меню уезжает) и может «застрять», если анимация закрытия модалки гонится с unlock.
- Делай лок **с владельцами** (Map owner → reason): две модалки = один лок, снимается,
  когда закрылась последняя. Сохраняй/восстанавливай исходные inline-стили.
- Внутри модалки скроллящемуся контейнеру: `overflow-y: auto; overscroll-behavior: contain;`.

## 3. Скролл, overscroll, pull-to-refresh, мигание

- На `html`, `body`, корне приложения: `overscroll-behavior-y: none` (убирает «резинку»
  и pull-to-refresh, который в standalone перезагружает/дёргает страницу).
- Если резинка всё равно мешает в app-роутах: глобальный `touchmove` (`passive: false`),
  который делает `preventDefault()` только при свайпе вниз, когда **ни один** предок цели
  не может скроллиться вверх (`scrollTop > 0`). Свайпы вверх и вложенные скроллеры не трогать.
- Для вложенных скроллеров (чат, лента в модалке) — `min-height: 0` у flex-ребёнка,
  `overflow-y: auto`, `overscroll-behavior-y: contain`. Экран чата — `position: fixed; inset: 0`
  вместо `height: 100dvh`.
- **`backdrop-filter` на мобильных — главный источник мигания и тормозов при скролле.**
  Отключай его под `@media (hover: none) and (pointer: coarse)` (или `max-width: 1024px`)
  для шапок, композеров, карточек, кнопок «вниз»; заменяй непрозрачным фоном.
- `background-attachment: fixed` на iOS не работает и дёргается — только `scroll`.
  Декоративные фоновые слои — `position: absolute`, не `fixed`.
- Не делай `scroll-behavior: smooth` на `html` для SPA.
- Бесконечная подгрузка (особенно чат вверх): префетч за ~1.5 экрана до края, а не
  за 72px; **якорь скролла измеряй после прихода данных, прямо перед изменением DOM**,
  иначе при инерционном скролле читателя отбрасывает назад (мигание).

## 4. Viewport, клавиатура, safe area

- Meta: `width=device-width, initial-scale=1, viewport-fit=cover` (+ `maximum-scale=1`,
  если нужно убрать автозум при фокусе; альтернатива — `font-size: 16px` у всех input/textarea/select).
  `apple-mobile-web-app-capable=yes`, `apple-mobile-web-app-status-bar-style=black-translucent`.
- Safe area — в CSS-переменных: `--safe-top: env(safe-area-inset-top, 0px)` и т.д.
  Применяй к шапкам, нижнему меню, полноэкранным модалкам, кнопкам закрытия
  (`top: max(1rem, env(safe-area-inset-top))`).
- Высота экрана: `--app-vh: 100vh` с `@supports (height: 100svh) { --app-vh: 100svh }` для
  min-height страниц (svh не прыгает при показе/скрытии панелей Safari). `100dvh` — для
  полноэкранных оболочек/модалок (`max-height: min(88dvh, 48rem)`). Голый `100vh` на iOS
  больше реального экрана.
- **Клавиатура: `dvh` НЕ уменьшается при открытой клавиатуре на iOS.** Для экранов с
  полем ввода внизу (чат, поддержка) бери высоту из `visualViewport`:
  `height = visualViewport.offsetTop + visualViewport.height - container.top`, слушай
  `visualViewport` `resize` **и** `scroll`, обновляй через `requestAnimationFrame`.
- Если контейнер внутри скроллящегося `<main>`, iOS позиционирует его fixed-детей
  относительно `<main>` (Android — нет). Лечится: телепорт в `body` + `top/height` из visualViewport.
- Не прячь/показывай меню по `focusin/focusout` — это вызывало мигание при фокусе.
  Если нужно скрыть меню при вводе — CSS: `html:has(input:focus, textarea:focus, [contenteditable]:focus) .dock { visibility: hidden }`
  (без анимаций), либо просто не прятать.
- Инпуты: `-webkit-appearance: none; appearance: none;` + явные `color`, `caret-color`,
  `-webkit-text-fill-color`, `color-scheme` (иначе тёмная тема даёт невидимый текст/автозаполнение).
  `-webkit-text-size-adjust: 100%` на `html`.
- Тач: `-webkit-tap-highlight-color: transparent; touch-action: manipulation;` на кнопках,
  `-webkit-touch-callout: none` там, где мешает системное меню долгого тапа (картинки-превью, табы).

## 5. Аудио и голосовые

- **Храни и отдавай только iOS-совместимые форматы**: MP3 (`audio/mpeg`) или AAC/M4A.
  OGG/Opus/WebM — конвертируй **на сервере при загрузке** (ffmpeg), а не надейся на клиент.
  Если конвертация упала — отклони загрузку, не сохраняй неиграбельный файл.
  `ffmpeg -i in -vn -codec:a libmp3lame -b:a 160k -ar 44100 out.mp3`
  Для уже лежащих файлов — разовый скрипт миграции.
- Telegram/WhatsApp-голосовые и `MediaRecorder` в Chrome/Android дают OGG/Opus/WebM —
  это ровно тот случай. На iOS `MediaRecorder` пишет mp4/aac — проверяй `MediaRecorder.isTypeSupported`.
- Сервер/хранилище должны поддерживать **Range-запросы (206)** и отдавать правильный `Content-Type`.
  Без этого Safari не играет или не перематывает. S3/MinIO/Garage — ок, свой эндпоинт — проверь.
- `play()` только из пользовательского жеста; обрабатывай промис:
  `NotAllowedError` → «нажмите ещё раз», `NotSupportedError` → «формат не поддерживается».
  Показывай ошибку в UI, а не глотай в `catch {}`.
- Подписанные URL (S3 presigned) протухают: при ошибке воспроизведения **один раз**
  запроси свежий URL и повтори (ключ `fileIndex:src`, чтобы не зациклиться).
- Сохраняй `playbackRate` при смене трека (iOS сбрасывает при новом `src`).
- Экран блокировки/фон: Media Session API (`metadata`, `setActionHandler` для
  play/pause/seek/next/prev, `setPositionState` в try/catch — поддержка неполная).
- Мини-плеер, переживающий навигацию, — один `<audio>` в корне приложения, не в странице.

## 6. Видео

- `playsinline` на каждом `<video>` (иначе iOS открывает полноэкранный плеер), `preload="metadata"`.
- MP4 должен быть **faststart** (moov в начале), иначе долгий старт/не играет по сети:
  `ffmpeg -i in -c copy -movflags +faststart out.mp4`.
- Не-MP4 (WebM, экзотика) и HEVC перекодируй в H.264 + AAC:
  `-c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p -c:a aac -movflags +faststart`.
- Превью-кадры в ленте: `poster` вместо автозагрузки видео, иначе мигание и трафик.

## 7. Скачивание файлов (самое болезненное)

В standalone-PWA `<a download>` + blob работает плохо/никак, `window.open` после `await`
блокируется, а файл, открытый внутри PWA, оставляет пользователя без кнопки «назад».
Финальные рабочие схемы:

| Что | iOS | Остальные |
|---|---|---|
| Видео (большие файлы) | одноразовый **подписанный тикет** → `location.href` на **другой домен** (вне scope PWA) с `Content-Disposition: attachment` | `fetch` → blob → `<a download>` |
| Картинки | `fetch` → `File` → `navigator.share({ files })` (сохранить в «Фото»); fallback — открыть blob в новом окне | `<a download>` |
| PDF/документы | **окно резервируется синхронно** в обработчике клика (`window.open('about:blank')`), потом ему ставится `location` = blob URL; просмотр PDF — нативно в новом окне, не в своём просмотрщике | `<a download>` |

Детали, без которых не работает:
- **Тикет**: `POST /download-ticket` (с авторизацией) → короткоживущий JWT (минуты) →
  `GET /download-ticket/:token` без заголовков (навигация не может нести `Authorization: Bearer`).
- **Другой поддомен** (`media.example.com`) — выход за scope PWA, iOS открывает системный
  просмотр/загрузку. Тот же origin = файл откроется внутри PWA.
- Заголовки ответа: правильный `Content-Type` (`video/mp4`, **не** `application/octet-stream`
  и **не** zip — оба варианта пробовали, хуже), `Content-Disposition: attachment; filename="ascii-fallback.mp4"; filename*=UTF-8''<percent-encoded>`,
  `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`.
- `navigator.share({files})`: сначала `navigator.canShare({ files: [file] })`; `AbortError`
  (пользователь закрыл шит) — не ошибка. Для больших видео share-шит падает по памяти —
  поэтому видео идёт через тикет, а не через share.
- Всё, что открывает окно, — вызывай **синхронно в обработчике клика** до первого `await`.
- `URL.revokeObjectURL` на iOS — с задержкой ~60 с (окну нужно время прочитать blob).
- Внутренние ссылки в пользовательском контенте (`/app/...` того же хоста) перехватывай и
  веди через роутер, иначе `target="_blank"` выкидывает из PWA в Safari.
- Сообщение об ошибке на iOS — конкретное («iPhone не смог передать видео… освободите память»)
  + отчёт в мониторинг.

## 8. Service worker, обновления, загрузка чанков

- iOS агрессивно держит старый SW/HTML. Нужна **явная стратегия релизов**:
  - эндпоинт `/release.json` (no-store) с id релиза; id вшивается в ассеты при сборке;
  - проверка на `visibilitychange→visible`, `focus`, `online` и по таймеру;
  - применять новый релиз **незаметно**: сразу после открытия (до первого тапа), при уходе
    в фон, или полной загрузкой на следующей навигации. Не перезагружать активного
    пользователя, никогда не перезагружать дважды подряд для одного релиза;
  - первый визит сохраняет id, который вернул сервер (иначе ложный «доступно обновление»
    у всех с чистым хранилищем — iOS чистит его).
- `registration.update()` + `postMessage({type:'SKIP_WAITING'})` вместо `unregister()`
  (unregister ломает push-подписку).
- **Ошибки загрузки чанков** после деплоя — нормальная ситуация на iOS. Ловить и делать одну
  перезагрузку (guard в storage на 5 мин): `Failed to fetch dynamically imported module`,
  `Importing a module script failed`, `Unable to preload CSS`, а также Safari-специфичное
  `undefined is not an object (evaluating 'x.default')` — **только** если недавно (≤15 с)
  была реальная ошибка ассета, иначе маскируешь настоящие баги.
- Держи старые хешированные чанки на сервере после релиза (клиенты со старым HTML их догрузят).
- Nuxt: `experimental.entryImportMap: false` (import maps ломали старый Safari).
- Скрипт регистрации SW — **legacy-синтаксис** (без `?.`, `??`, `1_000`), он выполняется
  на самых старых устройствах.
- HTTP/3 (QUIC) на некоторых iOS-путях молча роняет запросы (не доходят до логов) →
  на прокси оставь `h1 h2` (Caddy: `servers { protocols h1 h2 }`), пока не проверено.

## 9. Push-уведомления

- iOS: только **установленная** PWA и iOS ≥ 16.4. В Safari-вкладке — показывай инструкцию
  «Поделиться → На экран Домой», а не кнопку, которая ничего не сделает.
  Причины недоступности возвращай явно: `ios_install_required`, `ios_update_required`,
  `permission_denied`, `unsupported`.
- `navigator.serviceWorker.ready` и `Notification.requestPermission()` могут **висеть вечно** —
  оборачивай в таймаут (10 с) + общий watchdog на весь флоу (20 с) с логом зависшего шага.
- Модалка «включите уведомления» **всегда** должна иметь кнопку закрытия (не блокировать
  пользователя, если включить невозможно). Во время подписки — спиннер и текст.
- iOS сбрасывает подписку: храни `deviceId` (localStorage) и «предпочтение включено»;
  при старте, если предпочтение `true`, а подписки нет — тихо переподпишись.
- На сервере сериализуй параллельные subscribe по `user+device` (гонка → 500).
- Клик по уведомлению: фокусируй уже открытое окно приложения, нормализуй URL к своему origin.

## 10. Прочее

- Хранилище в Safari-вкладке чистится через ~7 дней без визитов; Safari и установленная
  PWA — **разные** хранилища и cookie-сессии. Сессию восстанавливай из httpOnly-cookie
  с ротацией refresh-токена, не полагайся только на localStorage.
- `beforeinstallprompt` на iOS нет — свой экран-инструкция установки.
- WebSocket после сна телефона «мёртв, но открыт»: на `visibilitychange→visible` пингуй и
  пересоздавай, если нет ответа за ~4 с; после реконнекта догружай пропущенные сообщения.
- Ховеры — только под `@media (hover: hover)`, иначе залипают после тапа.

## Симптом → причина (быстрый поиск)

| Симптом на iPhone | Смотри |
|---|---|
| Нижнее меню скачет/уезжает/посередине экрана | §1: предок с transform/contain? анимации на меню? iOS 26 → body-скроллер |
| Страница открывается не сверху после перехода | §1: скроллер = body, роутер сбросил window |
| После закрытия модалки скролл сломан/меню уехало | §2: `body position:fixed` лок |
| Мигание при скролле/фокусе | §3 backdrop-filter, §4 focusin-хэндлеры, §3 якорь подгрузки |
| Поле ввода спрятано клавиатурой | §4 visualViewport |
| Голосовое/аудио не играет | §5: формат OGG/Opus, Range, Content-Type, жест |
| Видео не играет/долго стартует/открывается на весь экран | §6 faststart, playsinline, H.264 |
| «Скачать» ничего не делает / открывает внутри PWA без выхода | §7 |
| После деплоя белый экран / ошибка модуля | §8 чанки, entryImportMap, legacy-синтаксис |
| Push пропадают через время | §9 переподписка по deviceId |

## Проверка без айфона

1. Автоматически: регрессионные тесты на CSS-инварианты (нет transform/animation на меню,
   есть `playsinline`, нет OGG в ответах и т.д.) + Playwright с WebKit — как первый фильтр
   (iOS-специфику safe-area/тулбаров/скачивания он не воспроизводит).
2. Клиентская диагностика в проде: при скролле/resize логировать `visualViewport`
   (height, offsetTop, scale), реальный скроллер, `scrollTop`, расстояние меню от низа
   вьюпорта; ошибки медиа/скачивания/чанков — с UA и версией iOS. Так баг виден из логов
   без устройства.
3. Ручной сценарий для человека с iPhone (выдай пользователю): установить PWA на экран
   Домой → длинная лента: инерционный скролл в обе стороны, смена направления → все табы
   меню → открыть/закрыть клавиатуру → модалка открыть/закрыть → голосовое → скачать
   видео/картинку/PDF → свернуть/развернуть приложение. Повторить в Safari-вкладке и на Android.
4. Облачные реальные устройства (BrowserStack/LambdaTest) или б/у iPhone со старой iOS.

## Как пополнять

Новый кейс = новая строка в «Симптом → причина» + правило в нужном разделе в формате
«делай / не делай / почему» (+ ссылка на WebKit-баг или коммит). Подробную историю
итераций — в `references/`. Не добавляй догадки: только то, что подтверждено на устройстве.
